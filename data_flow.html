CynLr CRM — Deal Journey Data Flow

Discovery → Qualification → Outreach → Engagement → Close  ·  Which domain changes at every step

CREATE New record inserted
UPDATE Existing record changed
SYNC →HS Pushed to HubSpot
LOG Activity entry added
D1 Person
D2 Company
D3 Deal
D4 Activity
1
Discovery
Lead identified
Person Company
You find a potential lead — via LinkedIn, event, referral, or cold research.
CREATE
Company companies
name domain industry segment geography icp_fit = Unknown
domain is the dedup key — if company already exists, skip CREATE and reuse existing id.
CREATE
Person persons
full_name linkedin_url company_id company_name source bucket event outreach_status = Pending poc_status = Cold priority = 5.0
outreach_status: Pending →Sent →Replied →Meeting Set →Closed
2
Research & Enrichment
Profile deepened
Person Company Activity
LinkedIn enrichment runs (via Apify or manual). Profile is deepened. ICP assessment made.
UPDATE
Person persons
headline position location college about photo_path enriched_at poc_status → Warm or ICP relationship_strength → 3
UPDATE
Company companies
icp_fit → Strong/Medium/Weak company_size website relationship_score
LOG
Activity activity_log
activity_type = Enrichment direction = Internal person_id company_id
3
Qualification & Deal Creation
Opportunity opened
Deal Junction → HS
You decide this person + company is worth pursuing. A deal is opened and the contact is linked as the champion.
CREATE
Deal deals
name company_id stage = Prospecting application_type lead_source amount = null technical_win = false budget_confirmed = false
CREATE
Junction deal_contacts
deal_id person_id role = Champion
Also set deals.champion_id = person_id (fast-access shortcut).
↗SYNC to HubSpot: create Deal object · set stage=Prospecting · associate Contact
4
First Outreach
Message sent
Person Activity Campaign
First message goes out — LinkedIn DM, email, or through a campaign.
LOG
Activity activity_log
activity_type = LinkedIn Message or Email direction = Outbound channel = LinkedIn or Email subject, body message_type = Cold tone status = Sent person_id, deal_id occurred_at = now
UPDATE
Person persons
outreach_status → Sent last_contacted_at = today next_followup_at = +7 days next_action = Follow up if no reply
UPDATE
Campaign campaign_recipients (if via campaign)
sent_at = now draft_id
Pending → outreach_status: Sent →Replied →Meeting Set →Closed
5
Follow-up Sequence
No reply yet
Person Activity
next_followup_at triggers. You send a follow-up. Repeat up to 3× before marking Skip.
LOG
Activity activity_log (one row per follow-up)
activity_type = Email or LinkedIn Message message_type = Follow-up status = Sent
UPDATE
Person persons
next_followup_at = +7 days last_contacted_at = today
After 3 touches with no reply: outreach_status → Skip. Deal stage may stay at Prospecting.
6
Reply & Engagement
They responded
Person Activity Deal
They reply. This is the first signal of intent. Relationship strength goes up.
LOG
Activity activity_log
activity_type = Reply direction = Inbound body = their reply text status = Received
UPDATE
Person persons
outreach_status → Replied poc_status → Warm relationship_strength → 5 next_action = Book discovery call
UPDATE
Deal deals
stage → Qualification action_item = Schedule discovery call
UPDATE
Campaign campaign_recipients (if via campaign)
reply_status = Replied
Pending →Sent → outreach_status: Replied →Meeting Set →Closed
7
Meeting Set
Call confirmed
Person Deal Activity → HS
Discovery call is booked. HubSpot syncs deal stage so the team can see it.
LOG
Activity activity_log
activity_type = Meeting channel = Video or In-Person status = Scheduled occurred_at = meeting date
UPDATE
Person persons
outreach_status → Meeting Set next_followup_at = call date
UPDATE
Deal deals
stage → Qualification action_item = Run discovery call action_due = call date
↗SYNC to HubSpot: deals.stage → Qualification · update action_item
Pending → Sent → Replied → outreach_status: Meeting Set →Closed
8
Discovery Call
Pain identified
Deal Activity
First real conversation. MEDDIC fields start filling in. Pain point confirmed.
LOG
Activity activity_log
activity_type = Call direction = Inbound body = call notes / summary occurred_at = call time
UPDATE
Deal deals — MEDDIC starts
stage → Discovery pain_point = "..." champion_id = person_id blockers = "..." action_item = Send product info
UPDATE
Person persons
relationship_strength → 6 poc_status → ICP (if confirmed)
↗SYNC to HubSpot: pain_point · blockers · champion · stage → Discovery
9
Technical Demo / POC
Product shown
Deal Junction Activity
Product demo or POC runs. More stakeholders enter the picture. Technical win flag is set if POC passes.
LOG
Activity activity_log (one per meeting)
activity_type = Meeting channel = Video body = demo notes
CREATE
Junction deal_contacts — new stakeholders added
person_id (technical contact) role = Technical
UPDATE
Deal deals
stage → Demo / POC technical_win = true ← if POC passed action_item = Prepare commercial proposal
↗SYNC to HubSpot: stage · cynlr_technical_win
10
Proposal
Commercial sent
Deal Junction → HS
Commercial proposal goes out. Economic buyer is identified. Budget discussion begins.
UPDATE
Deal deals
stage → Proposal Sent amount = $X expected_close = date probability = 40 economic_buyer_id = person_id product_services = "..."
CREATE
Junction deal_contacts — economic buyer added
person_id (economic buyer) role = Economic Buyer
LOG
Activity activity_log
activity_type = Email message_type = Proposal subject = Proposal: CynLr Vision System
↗SYNC to HubSpot: amount · expected_close · stage · economic_buyer
11
Negotiation
Budget confirmed
Deal Person Activity
Back and forth on terms. Blockers surface. Budget is confirmed or not.
UPDATE
Deal deals
stage → Negotiation budget_confirmed = true ← when confirmed blockers = "procurement process, 3 quotes needed" competitors = "..." amount = revised $Y probability = 70
UPDATE
Person persons (all stakeholders)
relationship_strength → 7–8
LOG
Activity activity_log — one row per touchpoint
Call / Email / Note per exchange
↗SYNC to HubSpot: amount · stage · blockers · cynlr_budget_confirmed
12
Closed Won / Lost
Deal terminal state
Deal Person Activity → HS
Deal closes. All fields finalised. Both local DB and HubSpot marked closed.
UPDATE
Deal deals
stage → Closed Won or Closed Lost hs_is_closed = 1 probability = 100 or 0 close_date = today
UPDATE
Person persons (champion + all stakeholders)
outreach_status → Closed relationship_strength → 9 (Won) or 4 (Lost)
LOG
Activity activity_log
activity_type = Note body = Close reason / lessons learned direction = Internal
↗SYNC to HubSpot: stage → Closed Won/Lost · close_date · mark deal closed
Pending → Sent → Replied → Meeting Set → outreach_status: Closed
