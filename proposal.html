Why We're Changing
🔴 Problem 1 — Data Clones
company is a free text field on every contact. BMW appears 47 times. No account-level view. Can't say "all contacts at BMW" without a messy search.
✅ Fix — companies table with domain dedup
One row per company. All contacts reference it via company_id. Account intelligence stored once. All views derived from it.
🔴 Problem 2 — Split Status Systems
outreach.status and campaign_recipients.reply_status are separate and can drift. A campaign can mark someone "Sent" while the contact still shows "Pending".
✅ Fix — Campaign sends write back to outreach
One status state machine. Campaign sends trigger outreach.status update automatically. Single source of truth.
🔴 Problem 3 — No Track Separation
No way to tell if a contact came from a cold discovery batch or an organic intro. Can't segment reporting, filter by campaign eligibility, or track approval rates.
✅ Fix — entry_source + batch_id on persons
entry_source = cold | organic | inbound | referral. Every cold contact is linked to a discovery_batches row. Cohort analysis enabled.
🔴 Problem 4 — Nikhil Review Has No Home
Approval decisions from Nikhil's swipe review are not stored anywhere in the CRM. After the review, there's no data trail. Can't filter "show me only contacts Nikhil approved".
✅ Fix — contact_reviews table
One row per review decision. reviewer, decision, notes, reviewed_at. Stored separately from persons — contact stays clean. Multiple reviewers supported.
Two Distinct Tracks — Same Database

Batch · AI-driven · Review-gated · 10 stages

C1 AI Discovery C2 Enrichment C3 Swipe Review C4 Approval Sync C5 List Build C6 Campaign Setup C7 Message Draft C8 Your Approval C9 Schedule & Send C10 Reply Tracking

🤝 Organic Track

Manual · Individual · Relationship-first · 5 stages

O1 Meet & Import O2 Log Conversation O3 Follow-Up Loop O4 Deal Signal O5 HubSpot Promote
⬡ Both tracks converge at Meeting Set — one deal record, one HubSpot sync, one shared pipeline from there.

Hosting Strategy

📁 Now — SQLite Local

Single file database with WAL mode already enabled. Fast, zero infra, good for single user. Keep this for development and solo use.

☁ Next — Postgres on Supabase (free)

Same schema, SQLAlchemy abstraction layer. Shared access for Vatsal + Nikhil. Always-on. No laptop dependency. One migration step — no query rewrites needed.

🔌 Add-on Pattern

Every new feature follows: new table with FK → contacts, new _migrate() block, new interaction rows for events. No schema rewrites, just additive growth.

🔄 HubSpot Sync Rule

Push to HubSpot only when outreach_status = Meeting Set. Keeps HS pipeline clean — no junk prospects, only real deals.
